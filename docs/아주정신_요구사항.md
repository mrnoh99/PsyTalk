## 2. 역할·권한 (`role`)

| 역할 | 인원 | 권한 |
|------|------|------|
| **superadmin** (전체관리자) | 1명 | 모든 방·멤버·권한 관리, **과 전체공지** 및 **캘린더** 작성, 방별 **참석 멤버** 지정 |
| **admin** (관리자) | superadmin이 지정 | superadmin과 동일하게 **과 전체공지**·**캘린더** 작성 가능 |
| **user** (멤버) | 그 외 | 소속 방에서 정책에 따른 읽기/쓰기 |

### 공지 방 작성 정책 (`post_policy`)

- `restricted`: **superadmin + admin + 방별 지정 작성자**만 글·일정 작성 (예: 과 전체공지)
- `members`: 해당 방 **참석 멤버** 누구나 작성

### 방 참석

- 각 방에 누가 들어갈지는 **전체관리자(superadmin)** 가 `room_members`로 지정

## 4. 기본 방 2개 (우선순위 `sort_order` 1~2)

| 순서 | 방 이름 | category | post_policy | 비고 |
|------|---------|----------|-------------|------|
| 1 | 전체공지 | notice | restricted | 관리자·지정 작성자 |
| 2 | 학술활동 | notice | members | `default_view = week` (주간 보기 기본) |

- 화면: 위 2개가 **기본 방**으로 항상 상단에 `sort_order` 순 표시
- **모임 방** (`category = custom`): **사용자가 카톡처럼 직접 생성**(이름 + 참여 멤버 선택).
  생성자 `created_by`, 참석자 `room_members`. 모임방은 **멤버·생성자·관리자에게만** 표시(RLS).
- **방 이름 수정**: 생성 후에도 방 헤더의 ✏️ 로 이름 변경 가능 — **방 생성자 본인 + 관리자**(기본 방은 관리자만).
  RLS `rooms_update_owner_admin` (`supabase/room_create.sql`). iOS·Android·Web 공통.

시드 SQL: `supabase/seed_rooms.sql` · 생성 권한/가시성: `supabase/room_create.sql`

## 5. 채팅 · 멀티 방 게시

- 한 방에서 글 작성 시:
  - **이 방만** / **다른 방에도** 선택
- 선택 가능한 방 = 작성자가 **접근 권한이 있는 방**만 (중복 게시 방지)
- 구현: `message_cross_posts` (원본 메시지 + 대상 `room_id` 목록)

## 7. 자료실 (방별)

- **캘린더에 올린 첨부** + **직접 업로드** 자료를 한곳에 모음
- 정렬: **날짜순** / **키워드별**
- 표시: **파일명(일부)** + **업로드 시 설명문**
- 저장: **별도 스토리지 서버** = **Supabase Storage** `room-files` 버킷 (`storage_setup.sql`)

## 9. Supabase 설정 순서

1. `fix_signup.sql` — 회원가입·profiles
2. `schema_extension.sql` — room_members, writers, calendar_events, room_files + RLS
3. `storage_setup.sql` — `room-files` 스토리지 버킷·정책 (자료실/첨부)
4. `seed_rooms.sql` — 기본 12방
5. `install.sql` — GRANT·RLS
6. `realtime_setup.sql` — Realtime publication (거의 실시간 앱 동기화)

> `schema_extension.sql` 은 `profiles` 조회 정책을 "본인만"에서 "인증 사용자 전체"로
> 바꿉니다(작성자·업로더 이름 표시용). 캘린더/자료실 작성은 현재 `owner=본인`만 검사하며,
> 방 참석(`room_members`) 기반 제한은 해당 기능 연동 시 강화합니다.
